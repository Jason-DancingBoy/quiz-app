> 创建日期：2026-08-06
> 岗位对标：AI Agent 开发工程师（初-中级，参考 2026 年市场 JD）
> 面试形式：纯口答 + 口述设计题（不写代码）
> 建议时长：45–60 分钟

## 一、面试流程总览

| 阶段 | 模块 | 时长 | 占比 | 考察目标 |
|---|---|---|---|---|
| 1 | 开场破冰 | 3 min | — | 缓解紧张，摸清他 demo 大概 |
| 2 | 概念层 | 8 min | 20% | 是否真懂 Agent，还是背概念 |

## 二、岗位要求速览（面试官背诵版）

初级 AI Agent 开发岗，2026 年市场的硬性要求就 5 条：

1. **LLM 应用开发**：会调 LLM API，理解 prompt、temperature、上下文窗口
2. **RAG 全链路**：切块 → Embedding → 向量库 → 检索 → 拼 prompt
3. **Function Calling / Tool Use**：Agent 调用工具的机制
4. **Agent 框架**：LangChain / LangGraph / OpenAI Agents SDK 至少熟一个
5. **工程素养**：异步、异常处理、可观测性、成本控制

加分项：MCP 协议、Eval 评测、多模态。C++ 背景是加分项（工程思维可迁移）。

**面试官参考标准库**：本机 quiz-app 项目就是标准 RAG 实现（FastAPI + ChromaDB + BGE Embedding + DeepSeek），可作为判断他回答对错的参考答案。

## 三、完整问题清单（含参考答案要点）

### 阶段 2：概念层（8 min）

**Q1. 「你觉得 AI Agent 是什么？和普通 Chatbot 有什么区别？」**
- 合格：Agent = LLM + Planning + Memory + Tools；能自主拆解并执行多步任务
- 优秀：能说出 Agent 会「决定下一步做什么」，Chatbot 只是「接一句回一句」
- 危险信号：只回答「有记忆的聊天机器人」

**Q2. 「什么时候该用 Agent，什么时候用固定流程（Workflow）就够了？」**
- 合格：任务流程不确定/需要动态决策 → Agent；流程固定 → Workflow（更便宜、可靠、可调试）
- 优秀：能主动提到 Agent 成本高、不可控，不是万能的
- 追问：「你写的 demo 里，哪些步骤其实用固定流程更合理？」

**Q3. 「说说 Agent 的 Memory——短期和长期记忆有什么区别？」**
- 合格：短期=对话上下文（context window）；长期=外部存储（向量库/数据库），跨会话
- 优秀：提到上下文窗口溢出怎么办（总结压缩 / 检索关键信息）

### 阶段 3：核心机制（12 min）

**Q4. 「Function Calling 的原理是什么？LLM 怎么知道该调哪个函数？」**
- 合格：开发者先声明工具 schema（函数名+参数描述）→ LLM 输出结构化 JSON（函数名+参数）→ 程序执行并回填结果 → LLM 继续回答
- 优秀：提到 LLM 并不真正执行函数，只是「决定调用」，参数可能生成错误需要校验

**Q5. 「为什么要做 RAG？幻觉怎么缓解？」**
- 合格：RAG 解决知识时效 + 幻觉（让模型基于检索到的真实资料回答）
- 优秀：能说出「先检索再回答」的流程，或提到检索不到时应该明确说不知道
- 参考：quiz-app 的文档→切块→Embedding→ChromaDB→检索→DeepSeek 链路

**Q6. 「切块 chunk size 怎么定？太大/太小有什么问题？」**
- 合格：太小→语义断裂、检索碎片化；太大→混入无关信息、超过窗口
- 优秀：提到需要按内容类型定、带重叠（overlap）保留上下文、切分时避开代码/表格

**Q7. 「Agent 需要查数据库 + 调 API + 检索知识库，中间结果怎么保存？」**
- 合格：对话历史/上下文里传递中间结果，或写成变量传给下一步
- 优秀：提到用状态管理（如 LangGraph 的 state）或结构化中间结果，避免上下文膨胀

### 阶段 4：工程素养（10 min，最拉差距）

**Q8. 「Agent 死循环了怎么办？」**
- 合格：设 max iterations / 最大轮数
- 优秀：加超时、token 预算上限、循环检测、任务「预算」概念
- ⚠️ 没做过真实项目的人大概率答不上来，这是核心区分题

**Q9. 「LLM 返回的 JSON 格式不对 / 解析失败，怎么办？」**
- 合格：重试几次；解析失败时把错误信息回喂给 LLM 让它修正
- 优秀：few-shot 示例、schema 校验、强制 JSON 模式（response_format）
- 危险信号：完全没想过这个问题

**Q10. 「怎么控制调用成本？」**
- 合格：选便宜的模型、减少无谓轮次
- 优秀：缓存重复请求、估算 token 用量、任务分级（简单任务用便宜模型）
- 参考：quiz-app 用 DeepSeek 而非 GPT-4，本身就是成本策略

**Q11. 「LLM API 超时/挂了怎么办？」**
- 合格：重试 + 指数退避
- 优秀：fallback 到备用模型、缓存兜底结果、降级提示用户

**Q12. 「Agent 输出每次都不一样，你怎么测试它？」**
- 合格：固定 prompt 让输出尽量稳定
- 优秀：建 eval 测试集，断言「关键内容」而非逐字匹配；区分功能测试（确定性）与效果评估（统计性）
- 提示：这题较难，答出任何合理思路都是加分

### 阶段 5：场景设计题（口述，8 min）

**Q13. 「设计一个客服 Agent，客户问『我的订单到哪了』，整个流程怎么走？」**
- 期望链路：意图识别 → 提取订单号 → 工具调用（查订单 API）→ 拿到结果组织回答 → 信息不足时追问澄清
- 追问1：「工具查不到这个订单，Agent 该怎么说？」→ 期望：诚实说查不到/让客户核对，不编造
- 追问2：「客户情绪激动骂人了怎么办？」→ 期望：安抚话术 + 判断是否需要转人工（safe fallback）

**Q14. 「如果这个客服 Agent 答错了一次，你怎么定位是哪里错了？」**
- 期望：加日志/链路追踪（每个环节记录：意图识别结果、检索到哪些资料、模型输出了什么）
- 优秀：提到可观测性（trace、token 用量日志）——再次加分

### 阶段 6：项目复盘（10 min，最真实）

> 以下为通用模板，面试前先了解他 demo 的具体功能，针对性调整。

**Q15. 「讲讲你的 demo：做了什么、整体架构、为什么这么设计？」**
- 听点：能否清晰讲出 输入→处理→输出 链路；自己选型的理由（而非照抄教程）

**Q16. 「踩过什么坑？怎么解决的？」**
- 听点：是否真实（坑的具体细节骗不了人）；解决问题的能力
- 常见候选：上下文溢出、prompt 不稳定、解析失败、API 限流

**Q17. 「如果用户量 ×100，哪里会崩？」**
- 合格：并发、超时、API 限流
- 优秀：缓存、队列、失败重试、降级
- ⚠️ C++ 背景的人答这类系统题通常有优势

**Q18. 「你日常用 AI Agent 帮你写代码——你怎么判断它给的代码是对的？」**
- 期望：跑测试、读代码理解而非盲信、让 AI 解释原理
- 考察点：批判性使用 AI 的能力，与「Agent 开发」岗位极度契合，答得好是大加分

## 六、面试官操作提醒

1. **先听完再追问**：他答完先不打断，追问用「然后呢？」「为什么？」「如果…会怎样？」
2. **防止背题**：概念题答得很顺时，立刻上一个场景题（Q13 类型）验真
3. **答错引导，不直接判死**：先问「还有别的思路吗？」再看是否真的不会
4. **时间控制**：Q12（测试）、Q14（定位问题）超出 2 分钟没思路就收，避免拖慢节奏
5. **打分时分开记**：概念分和工程分分开，别因为表达好就全给高分

## 7.2 关键验证题（按优先级排序）

### 🔴 Q-V1（全场第一题）RAGAS 三指标（Quiz-App）
「你简历写了评测 Context Relevancy / Context Precision / Faithfulness 三个 RAGAS 指标。分别说说这三个各自测什么？你在项目里实际落地了哪几个？」
- 满分回答：三个概念定义 + 「实际只落了 Faithfulness，另外两个研究过，因为我的场景是生成题不是问答，Context Precision 意义不大」→ **诚实 + 有判断力**
- 危险回答：「三个都用了，RAGAS 库自带的」→ 代码里没有，说明简历注水
- 追问：「那你的格式合规率和质量分是 RAGAS 还是自研的？」→ 期望：自研（`check_format_compliance` + `score_question_quality`）

### 🟡 Q-V2 限流的单进程问题（Quiz-App）
「这个项目生产部署了，限流 50 次/天是怎么实现的？如果部署两个 worker 进程会怎样？」
- 期望：内存计数 + 主动指出「多进程会失效、重启清零，应该用 Redis/DB」→ 工程意识强
- 危险：声称「存 DB/Redis」→ 与代码不符

### 🟡 Q-V3 JSON Schema 生成（Live-Edit）
「你说工具注册表自动生成 JSON Schema——怎么从 Python 函数签名生成？」
- 满分：诚实说「是手写的 input_schema，不是自动推断」+ 解释为什么手写更可控
- 危险：含糊其辞「用了 pydantic」→ 代码里没有

### ✅ Q-V4 记忆系统深挖（Live-Edit，最有价值）
「三阶记忆系统，短时记忆的『超窗截断 + 增量摘要』具体怎么触发的？」
- 期望：能讲出三档（`max_full_rounds` 内不动 → 超窗只截断 → 截断+LLM 摘要，超长只截断不再花 token 摘要）→ 说明真做过

「长时记忆『余弦+时效衰减+命中频次加权』，加权公式长什么样？」
- 期望：`final = cosine × exp(-rate×days) + hit_weight × min(hit,10)` 或接近的表述
- 深挖：「为什么命中次数要封顶 10？」→ 防热门 chunk 无限霸榜

「低层检索为空自动降级是什么意思？」
- 期望：L2 长时记忆无结果 → 降级到 L3 项目知识库（`if not memories_hit`）→ 逻辑清晰

### ✅ Q-V5 自愈评估深挖（Live-Edit）
「评估五阶段是什么？introspect（LLM 自查）判定通过的标准是什么？」
- 期望：能讲出「lint→test→preview→introspect→html_diff」+ 自查判定逻辑
- 高级追问：「introspect 用字符串判断『通过』两个字，会不会误判？怎么改？」→ 看他能否指出弱点（`passed = "通过" in text[:100] and "未通过" not in text[:100]`）
- 期望改进方案：正则/结构化 JSON 输出/让 LLM 输出布尔字段

### 🟡 Q-V6 崩溃恢复细节（Live-Edit）
「/continue 断点恢复，具体怎么保证崩溃后对话还能继续？」
- 期望：每轮持久化 messages + worktree 保留（TTL 内不删）+ 修复未配对 tool_use（Anthropic API 要求 tool_use 紧跟 tool_result，崩溃会留下孤儿块）
- 深挖：「什么情况下恢复会失败？」→ 能想到「worktree 被清理 / 没持久化到」加分

## 7.3 高级架构题（带一点 B）

### Q-A1 自研 vs 框架（Live-Edit）
「你自研 Agent Loop 不用 LangGraph，为什么？什么场景你会选框架？」
- 期望：自研理由 = 深度控制（审批、断点、审计、多模式）+ 学习成本；框架理由 = 团队协作、标准生态、多 Agent 编排
- 判断：能说出「自研 ≠ 高级，是取舍」→ 真懂

### Q-A2 Multi-Agent 设计
「两个 Agent 协作『读代码→改代码→跑测试』，你怎么分工和通信？」
- 期望：职责分离（读/改/测）+ 共享状态（worktree/文件）+ 结果交接（结构化消息）
- 深挖：「如果改代码的 Agent 和跑测试的 Agent 各说各话怎么办？」→ 共享仓库/文件系统作为「事实源」

### Q-A3 Agent 上生产会挂的三个点
「Live-Edit 上生产，最可能挂的三个点是什么？」
- 期望（参考）：① 死循环/token 爆炸（有 max_rounds 已防）② 工具误操作破坏代码（有 worktree+safety 已防）③ LLM 输出畸形 tool_use（有 _repair_messages）④ 成本失控
- 判断：能否用自己系统的机制举例说明「我已经防了 X」

### Q-A4 Agent 评测体系
「Agent 输出每次不一样，你怎么知道这次改动是变好还是变坏？」
- 期望：把 Quiz-App 的 RAGAS 思路迁移过来——固定场景集 + 指标（任务成功率/工具调用效率/最终结果匹配）+ 回归对比
